# プロジェクト計画

テキスト記法で書いた計画から、FBS・PBS・WBS・FBS と PBS の対応・役割分担・アローダイアグラム(クリティカルパス)・ガントチャート・担当者別ガントチャート・テスト項目(MOP)の表・サマリーを作るブラウザアプリです。
`index.html` 1 ファイルだけで動き、インストールやアカウントは要りません。外部のサービスを読み込まず、書いた内容をどこにも送信しません。

情報系の学生が、ハッカソンなどのプロジェクトで、機能(FBS)から製品(PBS)、作業(WBS)、担当、日程までを一続きに計画できるようになるためのツールです。絵を描くことよりも、計画の漏れや矛盾を見つけることと、日程を計算することに重点を置いています。

- テキストを 1 つ書くと、10 の図と表が自動で描かれる
- FBS と PBS の対応の漏れ、タスクのない PBS の要素、作成者(`by:`)のいないタスク、依存関係の循環を見つける
- 依存関係と日数からクリティカルパスを求める
- 担当者のタスクの重なりと休みを避けて日程を自動でずらし、ガントチャートを描く
- クリティカルパスの長さと、担当と休みを入れた日程の長さを並べて表示する
- 機能ごとのテスト項目(MOP)を一覧の表にし、チェック済みかどうかを表のチェックボックスで付けられる
- 担当者ごとにタスクを並べたガントチャートで、誰のタスクが多く誰が少ないか(作成の日数・稼働率)を比べられる。見出しのクリックで並べ替えもできる
- サマリーで、進み具合・予定との比べ(何日分遅れているか)・遅延と問題発生のタスク・担当者ごとの状況・MOP・警告を 1 枚で見られる
- タスクごとに進捗(実行前・実行中・完了・問題発生)を書くと、ガントチャートの棒の色が変わる。今日の線を引き、予定を過ぎて完了していないタスクに「遅延」と出す
- テキスト(.plan)で保存。図と表は 1 つずつ SVG・PNG・PDF で保存でき、表はタブ区切りでコピーできる(報告書用)。全部の図を 1 つの PDF にまとめて印刷することもできる(提出用)
- 生成 AI にテキストを書かせて、そのまま貼れる

## ほかのアプリとの関係

プロジェクト計画は単体で使えます。保存した計画書(`.plan`)は、[マイログ](https://mylog.sapp.jp)(日々の記録の照合)と[プロジェクト分析](https://projalysis.sapp.jp)(計画書の版の比較と、作業の集計)が読みます。

どのアプリをどう組み合わせるかは、使う人が決めます。組み合わせの例:

- 計画だけ: 計画を立て、図と表を報告書に使う
- 計画とマイログ: 計画書を読み込んで記録し、自分の担当のタスクの進み具合と問題の兆候を見る
- 計画とプロジェクト分析: 計画書を直すたびに保存して版を重ね、改訂の履歴と推移を見る
- 3 つとも: 各自のマイログをプロジェクト分析に集めて進み具合と問題の兆候を見、反映候補をもとに計画書を直して新しい版を保存する

## 使い方

公開版は https://plan.sapp.jp で使えます。
ダウンロードした `index.html` をブラウザで直接開いても使えます。

1. 公開版か `index.html` を、ブラウザ(Edge・Chrome など)で開きます。
2. 左の欄に計画を書きます。右に図が出ます。書き方は画面上部の「書き方」ボタンで見られます。
3. 画面上部の「ビュー」で、表示する図を切り替えます。
4. 右の図の要素をクリックすると、左のテキストの該当行が選ばれ、下に編集パネルが出ます(下の「図から編集する」)。

初めて開いたときは空です。「例を読み込む」を押すと、カレンダーアプリの開発の例が入ります。例の日付は、読み込んだ日が例の中の「今日」に当たるようにずらします。2 回目からは、前に編集していた内容の続きが開きます(下の「保存と読み込み」)。

## 生成 AI で計画を書かせる

入力がテキストなので、生成 AI が書いたテキストをそのまま貼るだけで図になります。
ただし、このアプリの記法は独自のものなので、AI は最初から書き方を知りません。

ChatGPT・Claude などの生成 AI に書いてもらうときは、最初に指示文 `docs/prompt_for_ai.md` の中身を AI に渡してください。記法と、警告が出ない計画にするための規則が書いてあります。

1. 指示文の中身を AI に貼る(またはファイルを添付する)
2. 続けて、計画の内容を伝える(例:「3 人で 3 週間、カレンダーアプリを作る計画。FBS・PBS・WBS を書いて」)
3. AI が書いたテキストを、左の欄に貼る
4. 左下に診断が出たら、「修正依頼をコピー」を押して AI に貼る。診断の内容とテキストに、書き方の要点を添えた依頼文がコピーされるので、AI が直したテキストを貼り直す

## 書き方

画面上部の「書き方」ボタンでも一覧を見られます。

```
start: 2026-04-23
end: 2026-05-14
off: sun, 2026-05-03..2026-05-06

members:
- 青木
- 井上 off: wed, 2026-05-20
- 上田

FBS: カレンダーアプリ
- 予定管理
  - 日時の設定 mop: 登録から表示まで 1 秒以内

PBS: カレンダーアプリ
- 画面/UI
  - 予定登録画面 realizes: 日時の設定

WBS: カレンダーアプリ
- 設計フェーズ by: 青木
  - 画面設計 for: 予定登録画面 days: 1.5 review: 上田 note: 配色は大学の指定に合わせる
  - 画面の実装 for: 予定登録画面 days: 3 after: 画面設計
```

- 階層は `- ` の字下げで作ります。前の行より深く字下げした行は、その行の子です。字下げの幅は自由で、空白でもタブでも構いません。
- 要素の属性は、名前の後ろに `予約語: 値` を並べて書きます。複数の値はカンマで区切ります。
- `//` から行末までは注です(行頭か、空白の後の `//` だけ)。

### 節

| 節 | 必須 | 書くもの |
|---|---|---|
| `version:` | | 最後にファイルとして保存した日(`YYYY-MM-DD`)。1 行目にだけ書ける。上書き保存・別名で保存のときにアプリが書く(なければ 1 行目に足す)。内容が変わっていなければ変えない。図には使わない。日程では、完了以外のタスクをこの日より前に置かない |
| `start:` | 必須 | 1 日目の日付(`YYYY-MM-DD`) |
| `end:` | | 期限。終了日(計算した日程の終わり)が超えたら警告 |
| `off:` | | 全員の休み。日付・範囲(`日付..日付`)・曜日(`mon` `tue` `wed` `thu` `fri` `sat` `sun`)をカンマで区切って書く。土日も作業日なので、休みにしたい曜日はここに書く |
| `members:` | 必須 | 次の行からメンバーを `- 名前` で書く。メンバーごとの休み(他の仕事など)は `off:` で書く |
| `FBS: 根の名前` | | 機能の木 |
| `PBS: 根の名前` | | 製品の木 |
| `WBS: 根の名前` | 必須 | 作業の木。末端の要素がタスク |

節の順は自由です(`version:` は 1 行目にだけ)。各節は 1 回だけ書けます。FBS・PBS を書かず、WBS 以降だけの計画にもできます。

### 属性

| 属性 | 書ける節 | 意味 |
|---|---|---|
| `mop:` | FBS | MOP(テストの評価項目)。同じ行に何度でも書ける |
| `mop*:` | FBS | チェック済み(試験を済ませた)の MOP。`mop:` と混ぜて書ける |
| `realizes:` | PBS | その要素が実現する FBS の要素 |
| `for:` | WBS | どの PBS の要素のためのタスクか |
| `days:` | WBS | タスクの日数(期間)。小数も書ける(3 桁まで、36500 日まで)。`by:` が複数人でも期間は同じ |
| `by:` | WBS | 作成者。複数人を書ける |
| `review:` | WBS | 確認者。複数人を書ける。日程には影響しない |
| `after:` | WBS | 先に終わっている必要がある要素。途中の要素を書くと、その下のタスクすべての後 |
| `status:` | WBS | タスクの進捗。`todo`(実行前)・`doing`(実行中)・`done`(完了)・`blocked`(問題発生)のどれか。書かなければ `todo`。末端のタスクにだけ書ける。完了以外のタスクは `version:` の日付より前に置かない(それ以外は日程の計算に使わない) |
| `note:` | すべて | メモ。図で要素を選ぶと下に出る |
| `off:` | members | そのメンバーの休み |

- `by:`・`for:`・`review:` は、親に書けば子が受け継ぎます。子に書けば、親の値を置き換えます。
- 途中の要素に書いた `after:` は、その下のタスクすべてに当てはまります。根の行には `after:` を書けません。
- 参照は名前で書きます。兄弟どうしで同じ名前は使えません。同じ名前が別の親の下にあって決まらないときは、`親::子` と書きます。
- 名前やメモの中に「空白 + 予約語 + 半角のコロン」(例 ` after:`)があると、そこから属性が始まったと読みます。名前やメモで使うときは、全角のコロン `：` にします。

### 書けないもの(構文エラー)

見出し(`#`)、番号付きのリスト、`* ` と `+ ` のリスト、太字(`**` `__`)、説明の文の行、コードブロック(```` ``` ````)、字下げや `-` の後の全角空白。名前に `,` と `::` は使えません。
`**` と `__` は、太字のつもりでなくても、名前と、名前を書く値(`for:`・`by:`・`after:` など)では構文エラーになります(`__init__.py` など)。`note:`・`mop:`・`mop*:` の文には書けます(文字のまま表示します)。

## 検査

図は描いたうえで、左下に次の警告を出します。

| 検査 | 内容 | 行う条件 |
|---|---|---|
| C1 | FBS の各要素を実現する PBS の要素がある | FBS と PBS があるとき |
| C2 | PBS の各要素が FBS の要素を実現している | FBS と PBS があるとき |
| C3 | FBS の各要素に MOP がある(`mop:` か `mop*:`) | `mop:` か `mop*:` を 1 つでも書いたとき |
| C4 | PBS の各要素のためのタスクがある | PBS があるとき |
| C5 | タスクすべてに作成者(`by:`)がいる | いつも |

- 途中の要素は、自分か子孫のどれかに対応があれば満たしたとみなします。根は検査しません。
- このほか、終了日が `end:` を超えたとき、タスクに `days:` がないか 0 のときにも警告を出します。

次のものはエラーで、直すまで図と日程を計算しません(直前の正しい図を薄く表示します)。

- 構文エラー
- 見つからない名前、決まらない名前
- 依存関係の循環
- 必須の節がない
- 休み(`off:`)のため、あるタスクの担当者全員が作業できる日が見つからない(日程を計算できない)

## 日程の計算

- クリティカルパスは、依存関係(`after:`)と日数だけから求めます。担当者と休みは考えません。
- ガントチャートの日程は、担当者のタスクの重なりと休みを避けて、タスクを自動でずらしたものです。最遅開始(遅くともこの時刻までに始める必要がある時刻)が早いタスクから順に、置ける最も早い日に置きます(同じなら書いた順)。同じテキストからは必ず同じ日程になります。
- 休みの日はタスクが止まり、休み明けに続きます。`by:` が複数人のタスクは、全員が作業できる日だけ進みます。
- 日数 0 のタスクは休みでずらさず、先行するタスクが終わった日に置きます。
- クリティカルパスの長さと、担当と休みを入れた日程の長さを並べて表示します。差が、担当の重なりと休みによる延びです。
- 完了以外(実行前・実行中・問題発生)のタスクは、1 行目の `version:` の日付(保存した日)より前の日には置きません。プロジェクトの途中で計画を直したときに、足したタスクやまだ終わっていないタスクが過去の日付に置かれないようにするためです。保存していない変更がある間は、実行前のタスクを、保存したときに付く今日の日付から置きます。実行中・問題発生のタスクは、保存するまでは前の `version:` の日付のままなので、遅れが見えます。保存すると、保存した日から置き直されます。
- 担当を入れた日程は、最短になるとは限りません。

## ビュー

| ビュー | 内容 |
|---|---|
| FBS | 機能の木。各要素の下に MOP を表示(チェック済みには ✓) |
| PBS | 製品の木 |
| FBS と PBS の対応 | 左に FBS、右に PBS を並べ、対応を線で結ぶ |
| WBS | 作業の木。管理番号(`1.2.3`)を自動で振る。タスクには日数と作成者を添える |
| アローダイアグラム | 丸が事象、矢印がタスク。矢印に管理番号と日数を付け、クリティカルパスを赤で示す。ダミー作業は自動で補い、点線で描く。下に最早開始・最遅開始・余裕の表 |
| 役割分担 | WBS の表に作成者・確認者・日数の列。下に担当者ごとのまとめ |
| ガントチャート | WBS の表と日付の目盛り。棒の色はタスクの進捗(実行前は白地に黒枠、実行中は青、完了は灰、問題発生はえんじ)で、左の表にも進捗の列がある。今日の線を引き、今日より前に終わる予定で完了していないタスクに「遅延」と出す。全体の休みは灰色、担当者の休みは斜線。期間が約 3 年(1096 日)を超えるときは描かない |
| 担当者別ガントチャート | 担当者 1 人につき 1 行で、その人のタスクの棒を日程どおりに並べる。左に作成の日数(横棒つき)・稼働率(作成の日数 ÷ その人が作業できる日数)・確認の件数。「作成の日数」「稼働率」の見出しを押すと、少ない順 → 多い順 → 書いた順と並べ替わる(表示だけで、保存はしない) |
| テスト項目(MOP) | 機能ごとの MOP の一覧表。済の欄にチェック済みかどうかを示し、実現する PBS の要素の列を添える。上にチェック済みの件数 |
| サマリー | 計画の概要、タスクの進み具合(進捗ごとの件数と日数、完了の割合)、予定との比べ(今日までに終わる予定の日数と完了した日数)、遅延と問題発生のタスクの表、担当者ごとの状況、MOP のチェック済みの割合、検査の警告の件数 |

検査の警告がある要素は、図で黄色の点線の枠になります。書いていない節が必要なビューでは、何が足りないかを表示します。

## 図から編集する

テキストが正本です。図での操作は、すべて左のテキストの書き換えとして行われ、図はそのテキストから描き直されます。1 回の操作は、左のテキスト欄で Ctrl+Z 1 回で戻せます。左のテキストにエラーがある間は、図からは編集できません。

書き込む前に、書き換えたテキストを確かめます。エラーになる値、別の要素の親子関係や属性が変わってしまう書き換え(字下げの幅がそろっていない木での追加・削除など)は書き込まず、理由を編集パネルに出します。

右の図の要素をクリックすると、下に編集パネルが出ます。

| 操作 | 内容 |
|---|---|
| 欄を書き換えて Enter(Tab で次の欄へ) | 名前・属性(`for:`・`days:`・`by:`・`review:`・`after:`・`realizes:`・`mop:`・`note:`・`off:`)を書き換える。欄を空にすると、その属性を消す |
| MOP の欄(FBS の要素) | 1 行に 1 つの MOP を書く(欄の中の改行は Shift+Enter)。文を直しても、並べ替えても、チェック済みかどうかは変わらない。増やした MOP は未チェック(`mop:`)で入る |
| 進捗の欄で選ぶ(タスクだけ) | 「実行前(todo)」などの 4 つから選ぶと、`status:` を書き換える。書いていないタスクで「実行前(todo)」を選んだときは何も書き足さない |
| 名前を変える | その要素を指している参照(`after:` など)も一緒に書き換わる |
| 子を追加・兄弟を追加 | 「新しい要素」の行を、正しい字下げで足す |
| 削除 | 下位の要素ごと消す。ほかの行から参照されているときは、その数を確認で知らせる |

ドラッグでも書き換えられます。

| ビュー | 操作 | テキストの書き換え |
|---|---|---|
| FBS と PBS の対応 | FBS の要素と PBS の要素の間をドラッグ | PBS の要素の `realizes:` に足す |
| FBS と PBS の対応 | 線をクリックして「この対応を消す」 | `realizes:` から除く |
| アローダイアグラム | 先のタスクの矢印から後のタスクの矢印へドラッグ | 後のタスクの `after:` に足す(循環する場合は足さない) |
| ガントチャート | 棒の右端をドラッグ | `days:` を変える(離した位置までの、休みを除いたタスクの長さを 0.5 の倍数にそろえる) |
| テスト項目(MOP) | 済の欄をクリック | `mop:` と `mop*:` を切り替える |

ドラッグは、Escape を押すか図の外で離すと取り消せます。

編集パネルの欄に書きかけがあるまま、ほかのボタン・欄・図を押すと、先に書きかけを書き込みます。書けない値だったときは、押した操作は行わず、理由を出して書きかけを残します(直すか、欄で Escape を押して取り消してください)。

ガントチャートで棒を動かして開始日を変えることはできません。開始日は、依存関係・担当・休みからアプリが計算します。

## 保存と読み込み

| 操作 | 内容 |
|---|---|
| 上書き保存(Ctrl+S) | 正本の左の欄のテキストを、開いているファイルに上書きする。まだファイルがないときは保存先を選ぶ |
| 別名で保存 | 保存先とファイル名を選んで、テキスト(.plan)を保存する |
| 表の題の右の「コピー」 | 表をタブ区切りの文字でコピーする(1 行目は見出し。表計算ソフトや Word の表にそのまま貼れる) |
| 図・表の題の右の「SVG」「PNG」 | その図・表 1 つだけを画像で保存する(PNG は 2 倍解像度)。表には題を入れない(報告書では題を表の上に書くため)。ファイル名は「元の名前_ビュー_図の識別子」か「元の名前_ビュー_表の題」 |
| 図・表の題の右の「PDF」 | その図・表 1 つだけを、同じ大きさの紙(余白なし)で印刷する。印刷の画面で「PDF に保存」を選ぶと、TeX にそのまま貼れる PDF になる |
| 印刷 / PDF | 描けるビューをすべて、1 ページに 1 つずつ印刷する(サマリーが先頭、残りはビューの選択欄の順)。印刷の画面で「PDF に保存」を選ぶと、全部の図が 1 つの PDF になる。サマリーのページは縦向き、ほかのページは横向きで、紙の大きさ(A4・A3 など)は印刷の画面で選ぶ。A4 横に収めると半分より小さくなる大きな図は、ページを分ける(木は第 1 層の要素ごと、表は行ごと、アローダイアグラムは図と表を別のページにし、表は縦向き) |
| 開く / ドラッグ & ドロップ | `.plan` `.txt`。版 0.30 までに「画像…」で保存した `.svg` も開ける |
| 新規 | テキストを空にする |

Chrome と Edge では、開いたファイルにそのまま上書きします。ほかのブラウザでは、ダウンロードとして保存します。
上の帯のファイル名の後ろの `*` は、保存していない変更があることを示します(図からの編集も含みます)。保存していない変更があるときに「新規」「開く」「例を読み込む」を押したり、ファイルを置いたりすると、確認が出ます。
保存すると、1 行目の `version:` がその日の日付になります(なければ 1 行目に足します)。開いた・保存したときの内容と、`version:` の日付のほかに 1 文字でも違うときだけ日付を変えます。違いがなければ、上書き保存は書き込まず、別名で保存は日付を変えずに書き込みます。テキスト欄の日付は書き込めてから替わり、Ctrl+Z で戻せます。正しくない場所(1 行目の行頭のほか)に `version:` があるときは、保存せずにその行を示します。図・表の保存(SVG・PNG・PDF)、印刷 / PDF、ブラウザへの自動保持では日付を変えません。
SVG を開いたときは、上書き保存で SVG を書き換えず、テキスト(.plan)の保存先を尋ねます。ページを開き直した後の最初の上書き保存でも、保存先を尋ねます。

ガントチャート・担当者別ガントチャート・サマリーの SVG・PNG・PDF には、保存した日の今日の線・遅延の印・予定との比べが入ります。

編集中のテキストは、このブラウザの `localStorage` にも自動で保持されます(どこにも送信されません)。ページを閉じても、次に開くと続きから使えます。ただし、次の点に注意してください。

- 保持先はブラウザごと、サイト(URL)ごとです。別のブラウザや別の場所の `index.html` で開くと、別の保持先になります。
- ブラウザの「サイトデータの削除」で消えます。残したい計画は、必ず「上書き保存」か「別名で保存」でファイルに保存してください。
- 保持できなかったときは、画面上部に警告が出ます。
- 同じ計画を 2 つのタブで開いて編集すると、片方の内容がもう片方を上書きします。その場合も警告が出ます。

保存する SVG には、テキストを埋め込みません(正本は .plan だけです)。版 0.30 までに保存した、テキストを埋め込んだ SVG は開けます。他のツールで描いた SVG や PNG は開けません。

## 報告書に載せる

- TeX: 図・表の題の右の「PDF」で作った PDF を `\includegraphics[width=\linewidth]{sample_gantt_gantt.pdf}` のように読み込みます(余白がないので、そのまま貼れます)。PNG も使えます。
- Word・スライド: 図・表の題の右の「SVG」か「PNG」で保存して貼ります。表は「コピー」で、Word の表として貼ることもできます。[シンプルスライド](https://slide.sapp.jp)には SVG をそのまま貼れます。

## 動作環境

Edge・Chrome などの最近のブラウザで動きます。印刷 / PDF と、図・表の題の右の「PDF」は、Chrome・Edge で使ってください(Safari 18.1 以前は紙の大きさの指定に対応しておらず、紙の大きさや余白が指定どおりにならないことがあります)。ネット接続が必要なのは公開版のページを開くときだけで、ダウンロードした `index.html` は接続しなくても動きます。
