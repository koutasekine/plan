# プロジェクト計画(plan.sapp.jp)仕様書

版 0.30(2026-10-27)

この文書は、アプリの外から見た仕様(テキスト記法、検査、日程の計算、ビュー、画面、保存)を定める。実装の作り方は定めない。実装は index.html(単一 HTML)で、この仕様書に沿って作る。

本文中の【提案】は、まだ承認を得ていない部分である。一覧は 12 章にまとめる。【提案】の付いていない部分は、確定した決定事項である。

## 1 章 目的と範囲

### 1.1 目的

FBS → PBS → WBS → アローダイアグラム(クリティカルパス) → 役割分担 → ガントチャートを、1 つのテキストから作る。ハッカソン2 で、情報系の学生に上流工程の感覚を学ばせるための道具である。

価値の中心は、絵を描くことではなく、整合性の検査と日程の計算にある。

### 1.2 範囲

- 範囲は、計画と、実行中に生じた修正である。計画を作る時点を前提にした仕組み(開始日が未来であることを求める、など)は入れない。
- 週次の実行データ(作業時間・TRL・TPM・テスト記録)の記録と集計は扱わない。
- 2 つのテキストの比較は扱わない。
- TPM、MOP の中身の解釈、MOP と試験のタスクの対応づけは扱わない。

### 1.3 S Apps としての前提

- 単一 HTML で、サーバーにデータを送らず、ネットなしで動く。
- 外部ライブラリを読み込まない。
- アプリ本体に Node.js を含めない。ビルドと検査に使うのはよい。
- 同じテキストからは、必ず同じ図と日程を出す(決定的)。ただし、今日の線・遅れの印・予定との比べ(ガントチャート・担当者別ガントチャート・サマリー。7.5 節・7.7 節・7.8 節)だけは、表示する日の日付で変わる。

### 1.4 名前

- アプリ名(上の帯・タブの題名): プロジェクト計画
- 公開先: plan.sapp.jp
- リポジトリ名: plan

## 2 章 用語

| 用語 | 意味 |
|---|---|
| 節 | `start:`・`end:`・`off:`・`members:`・`FBS:`・`PBS:`・`WBS:` の各行と、その下の要素の行のまとまり |
| 根 | `FBS:`・`PBS:`・`WBS:` の後ろに書いた名前の要素 |
| 要素 | 根と、`- ` で始まる行が表すもの |
| 末端 | 子を持たない要素 |
| 途中の要素 | 根でも末端でもない要素 |
| タスク | WBS の末端の要素(資料の「活動タスク」) |
| 属性 | 要素の行で、名前の後ろに書く `予約語: 値` |
| チェック済みの MOP | 試験を済ませた MOP。`mop*:` で書く(4.3 節) |
| 状態 | タスクの進み具合(実行前・実行中・完了・問題発生)。`status:` で書く(4.4 節) |
| エラー | 図と日程の計算を止める診断(10 章) |
| 警告 | 計算を止めない診断(10 章) |

## 3 章 テキスト記法

### 3.1 全体の形

```
start: 2026-04-23
end: 2026-05-14
off: sun, 2026-05-03..2026-05-06

members:
- 青木
- 井上 off: wed, 2026-05-20
- 上田

FBS: カレンダーアプリ
- 予定管理
  - 日時の設定 mop: 登録から表示まで 1 秒以内

PBS: カレンダーアプリ
- 画面/UI
  - 予定登録画面 realizes: 日時の設定

WBS: カレンダーアプリ
- 設計フェーズ by: 青木
  - 画面設計 for: 予定登録画面 days: 1.5 review: 上田 note: 配色は大学の指定に合わせる
```

- `-` の字下げで階層を作る部分だけが Markdown に由来する。それ以外は独自の記法である。
- 文字コードは UTF-8 とする。改行は LF と CRLF のどちらも読む。

### 3.2 行の種類

注(3.8 節)を取り除いた後、各行は次のどれか 1 つでなければならない。どれにも当たらない行は構文エラーとする。

1. **空行**: 空白とタブだけの行も含む。どこに置いてもよい。
2. **節の行**: 字下げなしで、予約語の `version`・`start`・`end`・`off`・`members`・`FBS`・`PBS`・`WBS` に `:` が続く行。
3. **要素の行**: 字下げ(0 個以上の空白・タブ)の後に `- `(ハイフンと半角の空白またはタブ 1 個以上)が続く行。ハイフンの後が全角の空白なら構文エラーとする。【提案】(全角の空白の部分)`members:`・`FBS:`・`PBS:`・`WBS:` の節の中にだけ書ける。

### 3.3 節の行

| 節 | 値 | 必須 | 下に要素の行 |
|---|---|---|---|
| `version:` | 日付 1 つ | 省略可 | 書けない |
| `start:` | 日付 1 つ | 必須 | 書けない |
| `end:` | 日付 1 つ | 省略可 | 書けない |
| `off:` | 休みの並び(3.5 節) | 省略可 | 書けない |
| `members:` | なし(後ろには何も書かない) | 必須 | 担当者を書く |
| `FBS:` | 根の名前と属性 | 省略可 | 書く |
| `PBS:` | 根の名前と属性 | 省略可 | 書く |
| `WBS:` | 根の名前と属性 | 必須 | 書く |

- 節を書く順は自由である。ただし `version:` は 1 行目にだけ、字下げせずに書ける。ほかの場所(字下げした行、2 行目以降)の `version:` は構文エラーとする。注の中や `note:` などの値の中の `version:` は、節の行ではない。
- 各節は 1 回だけ書ける。2 回書いたら構文エラーとする。
- 必須の節がなければエラーとする。
- `FBS:`・`PBS:`・`WBS:` の根の名前は必須である。
- 根の行にも、その節の要素と同じ属性を書ける(例: `WBS: カレンダーアプリ by: 青木`)。ただし `after:` は書けない(根の下の要素はすべて根の下位なので、依存関係が循環する)。【提案】
- `end:` の日付が `start:` より前ならエラーとする。【提案】

### 3.4 字下げと階層

- 字下げの深さは桁数で数える。空白は 1 桁、タブは次の 4 の倍数の桁まで進むものとして数える。空白とタブは混ぜてよい。
- 節の最初の要素の行は、字下げの深さによらず、根の子(`members:` では担当者)とする。
- 前の要素の行より深い行は、前の行の子とする。
- 前の要素の行と同じか浅い行は、同じ節の中で、それより前にある要素の行のうち、深さがその行以下で最も近い行の兄弟とする。該当する行がなければ、根の子とする。戻した深さが前のどの行と一致しなくてもエラーにしない。
- `members:` の担当者は子を持てない。担当者の行より深い行は構文エラーとする。
- 字下げに全角空白を使った行は構文エラーとし、全角空白であることを診断に示す。【提案】

### 3.5 値の書き方

**名前**

- 要素の行では、`- ` の後ろから、最初の「空白 + 属性の予約語 + `:`」の手前までを名前とする。前後の空白は除く。
- 名前は空にできない。
- 名前には空白を含めてよい。
- 名前に `,` と `::` は含められない(参照の区切りと衝突するため)。含めた場合は構文エラーとする。【提案】
- 名前の大文字と小文字、全角と半角は区別する。【提案】

**日付と範囲**

- 日付は `YYYY-MM-DD` の形だけを受け付ける。実在しない日付はエラーとする。
- 範囲は `日付..日付` と書き、両端を含む。始めが終わりより後ならエラーとする。

**曜日**

- `mon`・`tue`・`wed`・`thu`・`fri`・`sat`・`sun` の 7 つである。
- 毎週その曜日を休みとする。

**休みの並び**

- 日付・範囲・曜日を、カンマで区切って混ぜて書ける。例: `off: sun, 2026-05-03..2026-05-06, 2026-05-20`
- 期間(`start:` から終了まで)の外の日付を書いてもよい。

**日数**

- `days:` の値は 0 以上の 10 進数とし、小数を書ける。
- 小数点以下は 3 桁までとする。4 桁以上は構文エラーとする。【提案】
- 36500 日を超える値は構文エラーとする。【提案】これにより、内部では 1/1000 日を単位とする整数で正確に計算でき、余裕が 0 かどうかの判定が浮動小数点の誤差に左右されない。

**参照の並び**

- `realizes:`・`for:`・`by:`・`review:`・`after:` の値は、名前をカンマで区切って並べる。
- 各名前の前後の空白は除く。
- 同じ名前を 2 回書いたら警告とし、1 回とみなす。【提案】

**状態**

- `status:` の値は `todo`・`doing`・`done`・`blocked` のどれかとする(4.4 節)。大文字と小文字は区別する。

**自由な文**

- `note:`・`mop:`・`mop*:` の値は自由な文で、カンマで区切らない。
- 値は、次の「空白 + 属性の予約語 + `:`」の手前、または行末までとする。

### 3.6 属性

| 属性 | 書ける節 | 値 | 子が受け継ぐ |
|---|---|---|---|
| `off:` | `members:` | 休みの並び | ― |
| `mop:` | `FBS:` | 自由な文。同じ行に何度でも書ける | 受け継がない |
| `mop*:` | `FBS:` | 自由な文。同じ行に何度でも書ける(チェック済みの MOP) | 受け継がない |
| `realizes:` | `PBS:` | FBS の要素の名前の並び | 受け継がない |
| `for:` | `WBS:` | PBS の要素の名前の並び | 受け継ぐ |
| `days:` | `WBS:` | 日数 | 受け継がない |
| `by:` | `WBS:` | 担当者の名前の並び | 受け継ぐ |
| `review:` | `WBS:` | 担当者の名前の並び | 受け継ぐ |
| `after:` | `WBS:` | WBS の要素の名前の並び | 4.4 節 |
| `status:` | `WBS:` | `todo`・`doing`・`done`・`blocked` のどれか | 受け継がない |
| `note:` | すべての節の要素 | 自由な文 | 受け継がない |

- 書けない節に属性を書いたら構文エラーとする。
- `mop:`・`mop*:` 以外の属性を同じ行に 2 回書いたら構文エラーとする。
- 属性を書く順は自由である。
- 予約語の大文字と小文字は区別する。節の予約語の `FBS`・`PBS`・`WBS` だけが大文字で、ほかはすべて小文字である。
- `mop:` を同じ行に何度でも書けるのは、MOP の文に読点やカンマが入りやすいためである。【提案】
- `members:` の担当者にも `note:` を書ける。【提案】

### 3.7 名前と参照

- 兄弟どうしで同じ名前は禁止し、構文エラーとする。親が違えば同じ名前を使える。
- 担当者の名前は重複できない。
- 参照は、名前で行う。名前は次の範囲で探す。

| 属性 | 探す範囲 |
|---|---|
| `realizes:` | FBS の要素(根を含む) |
| `for:` | PBS の要素(根を含む) |
| `after:` | WBS の要素(根を除く) |
| `by:`・`review:` | `members:` の担当者 |

- 範囲の中に名前が 1 つだけあれば、それを指す。
- 1 つもなければ、未解決の参照としてエラーにする。
- 2 つ以上あれば、曖昧な参照としてエラーにし、候補を示す。このときは `親::子` の形で書く。
- 修飾名は必要な分だけ書けばよい(`単体テスト::カレンダー画面テスト`)。修飾名は、その並びが要素の祖先の並びの末尾と一致する要素を指す。根の名前も修飾に使える。【提案】
- FBS がなければ、`realizes:` は書けない(未解決の参照となる)。PBS がなければ、`for:` は書けない。

### 3.8 注

- `//` から行末までを注として読み飛ばす。
- `//` が注になるのは、行頭か、直前が空白・タブの場合だけとする。【提案】`note: https://example.jp/` のように URL を書けるようにするため。

### 3.9 構文エラーにするもの

上の規則に合わない行は、すべて構文エラーとする。生成 AI の書き癖を拒むため、とくに次のものは専用の診断文を出す。

| 書き方 | 判定 |
|---|---|
| 見出し | 字下げの後が `#` で始まる行 |
| 番号付きのリスト | 字下げの後が「数字 + `.` または `)` + 空白」で始まる行 |
| `*`・`+` のリスト | 字下げの後が `* `・`+ ` で始まる行【提案】 |
| 太字 | 名前または値に `**` か `__` を含む |
| 説明の文 | 3.2 節のどれにも当たらない行 |
| コードブロック | 字下げの後が ```` ``` ```` で始まる行 |

- `*` 1 個や `_` 1 個は、名前の中で使える(`snake_case` など)。
- 節の外(どの節より前)にある要素の行も構文エラーとする。

## 4 章 予約語の意味

### 4.1 `version:`・`start:`・`end:`・`off:`

- `version:` は、最後にファイルとして保存した日(その日付の版)である。1 行目にだけ書ける(3.3 節)。保存のときにアプリが書く(9 章)。手で書いてもよい。図・日程・検査には使わない。

- `start:` は 1 日目の日付である。
- `end:` は期限である。計算した終了日が `end:` を超えたら警告する。
- 全体の `off:` は、全員の休みである。
- 土日も作業日である。休みにしたい曜日は `off:` に書く。

### 4.2 `members:`

- 担当者を並べる。
- 個人の `off:` は、その人だけの休み(プロジェクト外の予定を含む)である。

### 4.3 FBS・PBS の属性

- `realizes:` は、その PBS の要素が実現する FBS の要素を指す。
- `mop:` は、その FBS の要素の MOP(テストの評価項目)である。ツールは中身を解釈しない。
- `mop*:` は、チェック済み(試験を済ませた)の MOP である。それ以外は `mop:` と同じに扱う(検査 C3 でも MOP として数える)。`mop:` と `mop*:` は同じ行に混ぜて書ける。

### 4.4 WBS の属性

- `for:` は、そのタスクがどの PBS の要素のためのタスクかを示す。
- `days:` は、その要素を作る実時間(期間)である。
  - `by:` に複数人を書いたときは、全員が `days:` の日数のあいだそのタスクにかかる(工数ではない)。
  - `review:` の有無で変わらない。
  - 途中の要素や根に書いたら警告とし、無視する。【提案】
- `by:` は作成者である。複数人を書ける。
- `review:` は確認者である。複数人を書ける。役割分担として記録・表示するが、日程には影響しない。
- `by:`・`for:`・`review:` は親の値を子が受け継ぐ。子に書いた場合は、親の値を置き換える(追加ではない)。根に書いた値も受け継ぐ。
- `after:` は、先に終わっている必要がある要素を指す。
  - 途中の要素を指したときは、その下のタスクすべての後を意味する。
  - 途中の要素に書いた `after:` は、その下のタスクすべてに適用する。子にも `after:` があるときは、両方を合わせる(置き換えない)。【提案】
  - 根の名前は `after:` に書けない(根の下の要素はすべて根の下位なので)。
  - 自分自身、自分の先祖、自分の子孫を指したら、循環としてエラーにする。【提案】
- `status:` はタスクの状態である。値と画面の表示は次のとおりとする。
  - `todo`: 実行前
  - `doing`: 実行中
  - `done`: 完了
  - `blocked`: 問題発生
  - 書かなければ `todo`(実行前)とみなす。
  - 上の 4 つ以外の値は構文エラーとする。
  - タスク(末端の要素)にだけ書ける。途中の要素や根に書いたら警告とし、無視する。親から子へは受け継がない。
  - 日程の計算には使わない。完了したタスクも、計算した日程の位置に描く。

## 5 章 検査

### 5.1 検査の項目

検査の結果はすべて警告とする。

| 番号 | 検査 | 行う条件 |
|---|---|---|
| C1 | FBS の各要素に、それを実現する PBS の要素が 1 つ以上ある | FBS と PBS がある |
| C2 | PBS の各要素が、FBS の要素を 1 つ以上実現している | FBS と PBS がある |
| C3 | FBS の各要素に MOP が 1 つ以上ある(`mop:` か `mop*:`) | FBS があり、FBS の中に `mop:` か `mop*:` が 1 つ以上ある |
| C4 | PBS の各要素に、それのためのタスクが 1 つ以上ある | PBS がある |
| C5 | タスクすべてに担当者(`by:`)がいる | 常に |

### 5.2 途中の要素の扱い

- 末端の要素は、自分自身に対応が必要である。
- 途中の要素は、自分自身に対応があるか、子孫のどれかに対応があれば満たしたとみなす。満たさない途中の要素も警告する。
- 根は検査しない。【提案】
- C4 の「それのためのタスク」は、受け継いだ `for:` を含めて数える。
- C5 の担当者は、受け継いだ `by:` を含めて数える。

### 5.3 検査ではなくエラーにするもの

次のものは計算ができないので、エラーとする。

- 構文エラー
- 未解決の参照、曖昧な参照
- 依存関係の循環(4.4 節の先祖・子孫への `after:` を含む)
- 必須の節がない
- 休み(`off:`)のため、あるタスクの担当者全員が作業できる日が、100 年先まで見つからない(日程を計算できない)

### 5.4 その他の警告

- 計算した終了日が `end:` を超えた
- タスクに `days:` がない。日数 0 として計算する。【提案】
- タスクの `days:` が 0 である(タスクの期間がないため)。
- 4.4 節で警告とした書き方

## 6 章 日程の計算

### 6.1 時間の単位

- 時刻 t は、`start:` の日の始まりを 0 とし、1 日を 1 とする実数で表す。日 d は区間 [d, d+1) である。
- 内部では 1/1000 日を単位とする整数で計算する。【提案】
- タスクは、休みの日には進まない。タスクの途中に休みがあれば、その分だけ終わりが延びる(タスクは中断して、休み明けに再開する)。
- タスクが進む日は、全体の `off:` に当たらず、かつ `by:` の全員が個人の `off:` に当たらない日とする。`by:` がないタスクは、全体の `off:` だけを見る。

### 6.2 クリティカルパス

- タスクと `after:` の依存関係だけから計算する。担当者と休みは考えない。
- 各タスクについて、最早開始・最早終了・最遅開始・最遅終了・余裕を求める。
- 余裕が 0 のタスクをクリティカルパスとする。
- クリティカルパスの長さは、最早終了の最大値(日数)である。

### 6.3 担当を入れた日程

担当者の重なりと休みを避けて、タスクを自動でずらす。

1. 6.2 節の最遅開始を優先度とする。
2. 先行するタスクがすべて置かれたタスクのうち、最遅開始が最も早いものを選ぶ。同じなら、テキストで先に書かれたものを選ぶ。
3. 選んだタスクを、次の条件を満たす最も早い開始時刻に置く。
   - 先行するタスクがすべて終わっている。
   - そのタスクの期間(開始から、休みを除いて `days:` だけ進んだ終了まで)、`by:` の全員がほかのタスクに就いていない。
   - 開始時刻は、そのタスクが進む日の中にある。
4. すべてのタスクを置くまで 2. と 3. をくり返す。

すでに置いたタスクの間に空きがあれば、その空きに入れてよい。

日数 0 のタスクは、休みに当たっても次の作業日へ送らず、先行するタスクがすべて終わった時刻に置く。担当者を占めない。日程の上では、先行が終わった日(時刻が日の始まりちょうどなら、その前の日)に属させる。先行がなければ 1 日目とする。

### 6.4 2 つの長さの表示

次の 2 つを並べて表示する。

- クリティカルパスの長さ(日数。6.2 節)
- 担当を入れた日程の長さ(`start:` から最後のタスクの終了日までの暦日数、およびその日付。6.3 節)

2 つの差は、担当の重なりと休みによる延びである。

## 7 章 ビュー

ビューの並びは次のとおりとする。ビューに必要な節がないときは、何が足りないかを表示する。

| 順 | ビュー | 必要な節 | 内容 |
|---|---|---|---|
| 1 | FBS | `FBS:` | FBS の木。各要素の下に MOP を小さく表示する(チェック済みには ✓ を付ける) |
| 2 | PBS | `PBS:` | PBS の木 |
| 3 | FBS と PBS の対応 | `FBS:`・`PBS:` | 対応の表。C1・C2 の警告の要素を示す |
| 4 | WBS | `WBS:` | WBS の木。管理番号を自動で振る |
| 5 | アローダイアグラム | `WBS:` | クリティカルパスを示す |
| 6 | 役割分担 | `WBS:`・`members:` | タスクごとの作成者と確認者 |
| 7 | ガントチャート | `WBS:`・`start:` | 担当を入れた日程と、タスクの状態 |
| 8 | 担当者別ガントチャート | `WBS:`・`start:`・`members:` | 担当者ごとのタスクの並びと、タスクの量(作成の日数・稼働率)の比べ(7.7 節) |
| 9 | テスト項目(MOP) | `FBS:` | 機能ごとの MOP の一覧表。チェック済みかどうかを示し、切り替えられる(7.6 節) |
| 10 | サマリー | `WBS:`・`start:` | 計画の概要と進み具合のまとめ(7.8 節) |

### 7.1 木のビュー(FBS・PBS・WBS)

- 根を上に置き、子を下に並べる木の図とする。【提案】
- 子がすべて末端のときは、子を親の下に縦に並べる。それ以外は横に並べる(横に広がりすぎないため)。【提案】
- WBS の管理番号は、階層の深さと子の数に応じて振り、桁数に上限を設けない。形は `1`・`1.2`・`1.2.3` とする。【提案】
- WBS のタスクの箱には、日数・作成者・確認者を小さく添える。【提案】
- 検査の警告がある要素は、黄色の点線の枠で示す。【提案】

### 7.2 FBS と PBS の対応

- スライド 10 枚目と同じく、左に FBS、右に PBS の要素を階層の字下げ付きで並べ、`realizes:` の対応を線で結ぶ。【提案】
- C1・C2 の警告がある要素は、黄色の点線の枠で示す。【提案】

### 7.3 アローダイアグラム

- スライドと同じく、丸が事象、矢印がタスクの形とする。
- 矢印には、スライド 15 枚目と同じく管理番号と日数を付ける。【提案】
- 2 つ以上の順位をまたぐ矢印は折れ線にして、丸やほかの矢印の上を通らないようにする。【提案】
- 図の下に、タスクごとの管理番号・名前・日数・最早開始・最遅開始・余裕の表を置く。【提案】
- 必要なダミー作業はツールが自動で補い、点線で描く。
- ダミー作業は、先行するタスクの組の包含関係(ある組が別の組に含まれる)を使って減らす。本数が最小になるとは限らない。【提案】
- クリティカルパスのタスクを強調する。
- 6.4 節の 2 つの長さを表示する。

### 7.4 役割分担

- スライド 16 枚目と同じく、WBS を表にし(途中の要素は下のタスクの行をまとめたセル)、タスクごとに作成者・確認者・日数の列を付ける。【提案】
- 表の下に、担当者ごとの作成するタスクの件数・作成の日数の合計・確認するタスクの件数の表を置く。【提案】
- 作成者・確認者がメンバー全員(2 人以上)のときは「全員」と書く(役割分担・ガントチャート・WBS の木で同じ)。

### 7.5 ガントチャート

- 目盛りは `start:` からの日付とする。
- 左はスライド 17 枚目と同じく WBS の表(途中の要素は下のタスクの行をまとめたセル)と担当者の列とし、タスクごとに 1 行とする。【提案】
- 担当者の列の右に状態の列を置き、「実行中」などを文字で書く(色の区別がつきにくい場合や、白黒で印刷する場合のため)。
- 目盛りは月・日・曜日の 3 段とする。【提案】
- タスクの棒は 6.3 節の日程で描く。休みの日は棒を切る。日数 0 のタスクはひし形で描く。【提案】
- 棒の塗りの色でタスクの状態を表す。実行前は白地に黒枠、実行中は青、完了は薄い灰、問題発生はえんじとする。図の上に凡例を置く。
- クリティカルパスはガントチャートでは示さない(アローダイアグラムで示す)。
- 今日の日付の列の始まりに縦線を引く(今日の列が図の範囲にあるとき。最後の列の翌日以降と、1 日目より前には引かない)。今日の日付は、表示する端末の日付とする。表示したまま日付が変わったら描き直す(今日の日付で変わるビュー、つまりガントチャート・担当者別ガントチャート・サマリーは図も描き直し、それ以外のビューでは編集パネルの表示だけを更新する。入力していた欄とカーソルの位置は保つ)。
- 今日より前の日に終わる予定で、状態が完了でないタスクは、棒の右に「遅れ」と書く。
- 全体の休みの日に網をかける。担当者の個人の休みは、そのタスクの行に斜線を引く。【提案】
- `end:` があれば、その日に縦線を引く。
- 図の期間(日程の終わりと `end:` の遅い方まで)が 1096 日(約 3 年)を超えるときは、描かずにその旨を表示する(年の打ち間違いなどで図が大きくなりすぎ、画面が固まるのを防ぐため)。
- 6.4 節の 2 つの長さを表示する。

### 7.6 テスト項目(MOP)

- 役割分担と同じ形の表とする。左は FBS の階層(途中の要素は下の行をまとめたセル)、続いて機能・済・テスト項目(MOP)・実現する PBS の要素の列を置く。
- MOP 1 つにつき 1 行とする。並びは FBS の木の順、同じ要素の中ではテキストに書いた順とする。
- MOP のない末端の要素は「(MOP なし)」の 1 行とする。検査 C3 の警告があれば、黄色の点線の枠で示す。
- 途中の要素や根に書いた MOP は、その要素の「全体」の行(「「名前」全体」)とする。
- 「済」の列は、`mop*:` ならチェックの入った四角、`mop:` なら空の四角とする。
- 「実現する PBS の要素」は、その FBS の要素を `realizes:` に書いた PBS の要素である(受け継がない。直接書いたものだけ)。PBS の節がなければ、この列を置かない。
- 表の上に、チェック済みの件数と MOP の件数を表示する。

### 7.7 担当者別ガントチャート

- 担当者 1 人につき 1 行とし、その人が作成者(`by:`)のタスクの棒を、6.3 節の日程どおりに並べる。複数人のタスクは、その全員の行に出す。`by:` のないタスクがあれば、最後に「(担当なし)」の行を置く。
- 左に次の列を置く。
  - 担当者: 名前。押すと、その担当者を選ぶ。
  - 作成の日数: その人が作成者のタスクの日数の合計。数と、担当者のうちいちばん多い人を最長とする横棒で示す(担当なしの行の横棒が、それより長くなるときは最長で止める)。
  - 稼働率: 作成の日数 ÷ その人が作業できる日数。作業できる日数が 0 日の担当者(すべての日が休み)は「―」とし、並べ替えではいちばん少ない側に置く。作業できる日数は、図の期間(1 日目から、日程の終わりと `end:` の遅い方まで)から、全体の休みと本人の休みの日を除いた日数とする。百分率の整数で示す。担当なしの行は「―」。
  - 確認: その人が確認者(`review:`)のタスクの件数。確認は日程を占めないので、件数だけを示す。担当なしの行は「―」。
- 行の並びは、`members:` に書いた順を既定とする。「作成の日数」「稼働率」の見出しを押すたびに、少ない順 → 多い順 → 書いた順と切り替える(同じ値なら書いた順。担当なしの行は常に最後)。並びは表示だけのもので、テキストにも自動保持にも残さない(開き直したとき、別の内容を開いたとき、新規・例を読み込んだときは書いた順に戻る)。並べ替えている列の見出しには ▲(少ない順)か ▼(多い順)を付ける。
- 棒の塗りは状態の色とする(7.5 節と同じ)。隣り合うタスクの棒が 1 本に見えないよう、塗りの棒には白い縁を付ける。棒には管理番号を書き、入りきれば名前も書く。棒を押すと、そのタスクを選ぶ。日数のドラッグはしない(ガントチャートで行う)。
- 凡例の説明の文は 2 行目以降に回す(図の幅が説明の文で広がりすぎないように)。
- 遅れ(7.5 節)のタスクは、棒の右上にえんじの丸を付ける(次のタスクの棒と重ならないよう、文字ではなく印にする)。
- 全体の休み・本人の休み・`end:` の線・今日の線・期間の上限は、7.5 節と同じとする。

### 7.8 サマリー

上から次の 7 つを並べる。

1. 計画の概要: 期間(`start:` 〜 `end:`)、今日の日付、クリティカルパスと担当と休みを入れた日程の 2 つの長さ(6.4 節)、タスクの件数、担当者の人数。
2. タスクの進み具合: 状態ごとの件数と日数の表、状態の色で塗り分けた日数の横棒、完了の割合(日数と件数)。
3. 予定との比べ: 今日までに終わる予定の日数と、完了した日数を並べ、予定より何日分遅れているか(進んでいるか)を示す。
   - 今日までに終わる予定の日数は、6.3 節の日程どおりに進んだとき、今日の始まりまでに済んでいるはずのタスクの長さの合計とする(全体の休みと担当者の休みの日は数えない)。
   - 完了した日数は、状態が完了のタスクの日数の合計とする。
4. 遅れと問題発生: 遅れ(7.5 節)か問題発生のタスクの表(管理番号・タスク・担当・予定の終わり・状態・遅れ)。行を押すと、そのタスクを選ぶ。
5. 担当者ごとの状況: 担当者ごとに、状態ごとの件数・遅れの件数・作成の日数の表。複数人のタスクは全員に数える。`by:` のないタスクがあれば「(担当なし)」の行を置く。担当者の行を押すと、その担当者を選ぶ。
6. テスト項目(MOP): チェック済みの件数と割合(横棒つき)。`FBS:` の節がなければ出さない。
7. 検査の警告: 警告の件数を項目(検査 C1〜C5・書き方・日程)ごとに示す。

- 3・4 の遅れと予定は、今日の日付で変わる(7.5 節の今日の線と同じ扱い)。

## 9 章 保存と読み込み

- テキスト: 拡張子は `.plan`。【提案】
- テキストの保存は、シンプルスライドと同じく「上書き保存」と「別名で保存」で行う。
  - 上書き保存: Chrome・Edge では、ファイル操作機能で開いた(または保存した)ファイルにそのまま書き込む。まだ上書きの先がなければ、別名で保存と同じに保存先を尋ねる。ファイル操作機能がないブラウザでは、ファイル名があれば同じ名前でダウンロードし、なければ別名で保存と同じにする。
  - 別名で保存: 保存先とファイル名を選んで保存する(名前の候補は今のファイル名、なければ「元の名前.plan」)。ファイル操作機能がないブラウザでは、ファイル名を尋ねてダウンロードする(拡張子がなければ `.plan` を付ける)。
  - Ctrl+S(Mac では ⌘S)で上書き保存する。
  - 上の帯にファイル名を出し、保存していない変更があれば後ろに ` *` を付ける。図からの編集もテキストの書き換えなので、同じく ` *` が付く。
  - 保存したら「(名前) に上書き保存しました(時刻)」を数秒出す。書き込みの間は保存のボタンを押せない。書き込みの間に編集したときは ` *` を残す。
  - 書きかけの欄があるまま Ctrl+S を押したときは、先に書きかけを書き込んでから保存する(書きかけが拒否されたら保存しない)。
  - 「別名で保存」の書き込み中に普通の編集をしたときは、保存先は新しいファイルに切り替え、` *` を残す。書き込み中に「開く」「新規」などで別の内容に替わったときは、いまの内容の保存先は変えない。
  - 書き込みに失敗してダウンロードで保存したときは、元のファイルへの上書きの先を忘れる(ファイルは消さない。次の上書き保存では保存先を尋ねる)。
  - テキストを入れ替える(開く・新規・例を読み込む・ファイルを置く)ときは、編集パネルの書きかけを捨てる。
  - 開けない拡張子のファイルを置いたときは、破棄の確認を出さずに、開けないことを知らせる。
  - 保存していない変更があるときに「新規」「開く」「例を読み込む」を押したり、ファイルを置いたりしたら、破棄してよいかを確かめる。
  - テキストを埋め込んだ SVG を開いたときは、その SVG を上書きの先にしない(上書き保存では `.plan` の保存先を尋ねる)。SVG は表示中のビュー 1 つ分の画像のため。
  - ページを開き直すと上書きの先は忘れ、次の上書き保存では保存先を尋ねる(シンプルスライドと同じ)。ファイル名と ` *` は自動保持に残す。
  - ドラッグ・アンド・ドロップで開いたテキストのファイルも、Chrome・Edge では上書きの先にする。
- `version:`(4.1 節): 内容が同じなら版も同じ、とする。
  - 比べる相手は、最後に開いたファイル(テキストを埋め込んだ SVG も含む)の中身か、最後に保存した中身とする。「新規」「例を読み込む」の後は比べる相手がない。比べる相手は自動保持に残し、ページを開き直しても使う。
  - 正しくない場所に `version:` があるとき(3.3 節の構文エラー)は、上書き保存・別名で保存をせず、「version: が正しくない場所にあります(○ 行目)。version: は 1 行目にだけ書けます。直してから保存してください」を出して、その行を選ぶ。ほかのエラーがあるときは、今までどおり保存できる。
  - 上書き保存・別名で保存のときは、今のテキストと比べる相手を、どちらも 1 行目の `version:` の日付の部分(`version:` の後ろから、注または行末までの値。前後の空白は含めない)だけを除いて、1 文字ずつ比べる。注・空白・`version:` の行の有無は比べる対象に残す。違えば(比べる相手がなければ)、書き込むテキストの `version:` をこの端末の今日の日付(日付だけ。時刻は入れない)にする。`version:` がなければ 1 行目に足し、あれば日付の部分だけを替える。
  - 違いがないときは日付を変えない。上書き保存は書き込まずに「変更がないので、保存しませんでした」を出す(日付の部分だけが違うときは「version: の日付のほかに変更がないので、保存しませんでした」)。別名で保存は、日付を変えずに書き込む。
  - テキスト欄の日付は、書き込みに成功してから替える。図からの編集と同じく、元に戻す(Ctrl+Z)の履歴に載る書き方で入れ、カーソルと入力の場所は書き換える前に戻す。取りやめたときや書き込みに失敗したときは、ファイルと同じくテキスト欄も変えない。書き込み中に編集していたときは、テキスト欄の 1 行目に `version:` があればその日付を替え(書き込み中に消された行は足し戻さない)、` *` は残す。
  - 画像(SVG・PNG)の保存、印刷 / PDF、自動保持では日付を変えない。
- 書き込むテキストは、改行を LF とし、BOM を付けない(開いたファイルが CRLF や BOM 付きでも同じ)。
- SVG: 「画像…」の選択欄で、表示中のビューを保存する。テキストを埋め込み、開き直せるようにする。
- PNG: 「画像…」の選択欄で、表示中のビューを保存する。
- 印刷 / PDF: 描けるビューをすべて、1 ページに 1 つずつ印刷する。印刷の画面で「PDF に保存」を選ぶと、1 つの PDF になる。
  - 並びは、サマリー → 残りのビューをビューの選択欄の順とする。必要な節がないビューは飛ばす。
  - A4 横の 1 ページ(内側の空きを除く)に収めると元の大きさの半分より小さくなるビューは、ページを分けて、そのビューの位置に続けて入れる。収まるビューは 1 ページのまま(画面の図と同じ)。サマリーは分けない。印刷の画面で選ぶ紙の大きさはページの側からは分からないので、判定は A4 横で行う。
    - FBS・PBS・WBS の木: 第 1 層の要素ごとに分ける。1 つの要素だけでも半分より小さくなるときは、その子ごとに分ける。各ページには、根からその要素までの道を描く。小さい要素は同じページにまとめる(まとめても大きく縮まない範囲で)。
    - 役割分担・テスト項目(MOP)・ガントチャート・担当者別ガントチャート: 行で区切り、各ページに見出しを付ける。途中の要素のまとめたセルは、ページの境目で切って描く。1 ページの行数は、図の幅で決まる縮み方より小さくならない範囲で多くする(幅のために半分より小さくなる図は、行で区切っても幅の分は縮む)。役割分担の担当者ごとのまとめは、最後のページに入らなければ次のページにする。テスト項目のチェック済みの件数は、全体の件数で示す。
    - アローダイアグラム: 矢印の図とタスクの表を別のページにする。タスクの表のページは縦向きとし、収まらなければ(縦向きの大きさで)行で区切る。矢印の図は分けない。
    - FBS と PBS の対応は分けない。
  - 各ページには図だけを置き、ファイル名や日付などの文字は足さない。テキスト(.plan)のページも作らない。
  - サマリーのページと、分けたときのアローダイアグラムのタスクの表のページは縦向き、ほかのページは横向きとし、紙の大きさは印刷の画面で選ぶ(A4 が既定で、A3 なども選べる)。図はページに収まるよう縮め、図の大きさより拡大はしない。
  - ページの余白は 0 とし、図の周りの空き(10 mm)はページの内側に取る。ブラウザが余白に日時・題名・アドレス・ページ番号を書かないようにするため(シンプルスライドと同じ)。
  - 担当者別ガントチャートの並びは、書いた順で印刷する。今日の日付で変わる図は、印刷した日の日付で描く。
  - テキストにエラーがあるときは印刷せず、その旨を知らせる。
- ガントチャート・担当者別ガントチャート・サマリーの SVG・PNG には、保存した日の今日の線・遅れの印・予定との比べが入る(表示したまま日付が変わっていれば、描き直してから保存する)。
- 保存のときに図の描き直しが残っていれば、先に描き直してから保存する(図と埋め込むテキストを食い違わせないため)。
- SVG・PNG のファイル名は「元の名前_ビュー」とする(例: `sample_gantt.svg`)。【提案】
- 読み込み: `.plan`(`.txt` も可)と、テキストを埋め込んだ SVG を開ける。【提案】(`.txt` の部分)
- 自動保持: 編集中のテキスト・ファイル名・保存していない変更があるか・`version:` の比べる相手を、テキストが変わるたびに、このブラウザの `localStorage` に保持する。どこにも送信しない。
  - 開いたときは、保持してある内容を続きとして開く。なければ空で開く。
  - 「新規」の後は空の内容を保持する(次に開くと空)。
  - 保持に失敗したとき(容量超過など)は、上の帯に警告を出す。
  - 別のタブで同じ計画が編集されたときは、上の帯に警告を出す(後から書いた方が残るため)。
  - 保持先はブラウザごと、サイト(URL)ごとである。ファイルへの保存の代わりにはならない。

## 10 章 診断

- 診断はエラーと警告の 2 段階とする。
  - エラーがあるときは、図と日程を計算しない。
  - 警告だけなら、すべて計算して描く。
- 件数の要約を出す。
- 項目ごと(構文・必須・参照・循環・日程・書き方・検査 C1〜C5)の一覧を出し、クリックで該当箇所を選ぶ。
- 各診断に行を付ける。
- エラーがあるときは、エラーだけを出す(検査と日程は計算しないので、その警告は出ない)。
- 「修正依頼をコピー」で、テキストと診断を、生成 AI に渡す形でクリップボードに写す。テキストはコードブロックで囲まず、「----- ここから -----」「----- ここまで -----」の行で挟む(コードブロックは構文エラーになるため)。【提案】

## 11 章 図からの編集

### 11.1 原則

- テキストが正本である。図での操作は、すべてテキストの書き換えとして行い、図の側にはデータを持たない。
- 書き換えた直後に、待たずにテキストを解析し直して図を描き直す。図はいつもテキストと一致する。
- ドラッグ中の線や日数の表示は、操作中だけの仮の表示である。手を離すとテキストに書き込み、図はそのテキストから描き直す。
- テキストにエラーがある間(図が薄い間)と、テキストを打った後で描き直しが済んでいない間は、図から編集できない。
- 1 回の操作は、テキスト欄の 1 回の書き換えとして行い、テキスト欄で Ctrl+Z 1 回で元に戻せる。テキスト欄で Tab キーで入れた空白も、元に戻す履歴に載る。
- 書き込む前に、書き換えたテキストを解析し直し、次をすべて満たすときだけ書き込む。満たさないときは、テキストを変えずに理由を編集パネルに出す。
  1. 新しいエラーが出ない(削除だけは、消した要素への参照のエラーを認める)。
  2. 操作の対象でない要素は、親子関係・名前・属性・参照先が変わらない。
  3. 操作の対象は、意図したとおりになる(書いた値がそのまま属性の値として読める、足した要素が意図した親の子になる、など)。
- このため、字下げの幅がそろっていない木で、要素を足したり消したりすると別の要素の親子関係が変わる場合は、書き込まない(テキストで字下げをそろえてから操作する)。

### 11.2 編集パネル

図の要素を選ぶと、下の編集パネルに名前と属性をテキストのとおりに出す。欄を書き換えて Enter を押すと(または欄から離れると)、テキストの該当行に書き込む。

| 要素 | 欄 | ボタン |
|---|---|---|
| 担当者 | 名前、休み(off)、メモ(note) | 担当者を追加、削除 |
| FBS の要素 | 名前、MOP(1 行に 1 つ。改行は Shift+Enter)、メモ(note) | 子を追加、兄弟を追加、削除 |
| PBS の要素 | 名前、実現する機能(realizes)、メモ(note) | 同上 |
| WBS の要素 | 名前、対象(for)、日数(days。タスクだけ)、状態(status。タスクだけ)、作成(by)、確認(review)、先行(after。根を除く)、メモ(note) | 同上 |

- 根は、兄弟の追加と削除ができない。
- 欄を空にすると、その属性を消す。
- 欄では、Enter(または欄から離れる)で書き込む。Tab で書き込むと次の欄へ、Shift+Tab では前の欄へ移る。Escape で書きかけをやめる。日本語入力の変換中の Enter では書き込まない。書き込んだ後も、入力は編集パネルに残る。
- 欄に書きかけのまま、編集パネルのボタン・別の欄・図の要素を押したときは、書きかけを書き込んでから、押した操作を行う(別の欄なら、その欄に入力を移す)。書きかけが拒否されたとき(書けない値のとき)は、押した操作は行わず、理由を出し、書きかけの値と入力をその欄に残す。書きかけを直すか、Escape で取り消してから操作する。書き換えにならない値(元と同じ意味の値)なら、そのまま押した操作を行う。ただし、テスト項目(MOP)の表の「済」の欄を押したときは、書きかけを書き込むだけでチェックは切り替えない(書き込みで MOP の並びや名前が変わると、押した MOP がどれか決まらないため。描き直した表で、もう一度押す)。
- 名前と値には、「空白 + //」(後ろが注になる)、「空白 + 予約語 + 半角コロン」(別の属性と読まれる)、`**`・`__` を書けない。名前には `,`・`::` も書けない。
- 名前を変えると、その要素(とその下位の要素)を指す参照(`realizes:`・`for:`・`after:`・`by:`・`review:`)も、新しい名前に書き換える。`親::子` の修飾名の中の名前も書き換える。名前を変えたために参照が一意に決まらなくなるときは、その参照を、一意に決まるいちばん短い修飾名に書き換える。
- 子を追加すると、下位の要素の最後の行の後ろに「新しい要素」(同じ名前があれば「新しい要素2」など)の行を足す。字下げは、すでにある子と同じ。子がなければ、親の字下げに空白 2 個を足す。兄弟を追加すると、下位の要素を含めた後ろに、同じ字下げの行を足す。足した要素を選んだ状態にする。【提案】(足す要素の名前と字下げ)
- 削除すると、下位の要素の行もまとめて消す。消す前に確認を出し、ほかの行からの参照の数も知らせる(消すと、その参照はエラーになる)。消した後は、どの要素も選ばない。
- MOP の欄は 1 行に 1 つの MOP を書く。欄の中の改行は Shift+Enter で入れる(Enter は書き込み)。元と同じ文は、並べ替えてもチェック済みかどうかを引き継ぐ。同じ文が 2 つ以上あって減らしたときは、チェック済みを残す。文を直した行は、元の位置で文だけを置き換え、`mop:` か `mop*:` かは元のままとする。元にない文の行は、並びの位置に `mop:` で足し、減った行は消す。
- テスト項目(MOP)の表で「済」の欄をクリックすると、その MOP の予約語を `mop:` と `mop*:` の間で切り替える(文は変えない)。
- FBS と PBS の対応の線を選んだまま、テキストや図で書き換えたときは、同じ要素どうしの線を選び直す(要素の名前で探す)。その線がなくなったときは、選択を外す。
- エラーの間の薄い図の要素を押しても、テキストの範囲は選ばない(薄い図は古いテキストの位置を持っているため)。
- ガントチャートの棒の右端(日数を変えるつまみ)をクリックすると、そのタスクを選ぶ。
- 状態の欄は 4 択で、「実行前(todo)」「実行中(doing)」「完了(done)」「問題発生(blocked)」と表示する。選ぶとすぐ書き込む。`status:` が書いてあれば、その値だけを置き換える。書いていないタスクで「実行前(todo)」を選んだときは、何も書き足さない(省略と同じ意味のため)。

### 11.3 ドラッグ

| ビュー | 操作 | テキストの書き換え |
|---|---|---|
| FBS と PBS の対応 | FBS の要素と PBS の要素の間をドラッグする(どちらから引いてもよい) | PBS の要素の `realizes:` に FBS の要素を足す |
| FBS と PBS の対応 | 線を選び、編集パネルの「この対応を消す」を押す | `realizes:` からその要素を除く(最後の 1 つなら属性ごと消す) |
| アローダイアグラム | 先に終わるタスクの矢印から、後のタスクの矢印へドラッグする | 後のタスクの `after:` に先のタスクを足す |
| ガントチャート | タスクの棒の右端をドラッグする | `days:` を変える。値は、タスクの始まりから離した位置までに作業できる長さ(全体の休みと担当者の休みの日を除く)を、0.5 の倍数にそろえたもの(0.5 日以上) |

- 参照に書く名前は、その節で一意に決まるいちばん短い修飾名とする。
- 依存の追加は、循環になる場合と、すでに先行である場合(推移的なものも含む)は書き換えない。上位・下位の要素どうしも結ばない。
- ドラッグは、Escape を押すか、図の外で離すと取り消す。
- 要素を押して動かさずに離したときは、ドラッグではなくクリック(要素を選ぶ)として扱う。
- ガントチャートで棒を動かして開始日を変える操作はない(開始日は依存関係・担当・休みから計算するため)。
